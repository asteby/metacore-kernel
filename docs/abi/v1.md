# Metacore ABI v1.0 — Stable Contract

> **Status:** Frozen as of 2026-05-13 with kernel `v0.10.1`.
> **Audience:** Addon authors targeting the metacore platform AND implementers
> of alternative host runtimes that want to be wire-compatible with `metacore-kernel`.
> **Scope:** Everything an addon (WASM guest module + manifest + bundle) MUST
> rely on to be portable between kernel patch / minor releases inside the v1.x
> series.
>
> **Compatibility promise:** Anything documented here is part of the stable
> ABI. Breaking changes require bumping to v2 and ship with at least one minor
> release of overlap during which v1 keeps working — see the
> [Stability](#stability--compatibility) section.
>
> Anything **not** documented here is implementation detail. The kernel may
> change it at any time. If your addon depends on undocumented behaviour and
> breaks, that is not a regression.

## 1. Scope of v1

ABI v1 is the union of four wire surfaces an addon depends on. They are
versioned together: a v1-compatible addon installed on any v1-compatible
kernel MUST work without recompilation.

| Surface           | What it is                                                                | Owning package          |
| ----------------- | ------------------------------------------------------------------------- | ----------------------- |
| Manifest schema   | The JSON document inside `manifest.json`                                  | `manifest/manifest.go`  |
| Bundle format     | The `tar.gz` layout an addon ships in                                     | `bundle/bundle.go`      |
| WASM ABI          | Guest exports + return-value encoding                                     | `runtime/wasm/abi.go`   |
| Host imports      | The `metacore_host` module exposed to guests                              | `runtime/wasm/capabilities.go` |

Everything else (HTTP routes, the dynamic CRUD endpoints, the WebSocket
protocol, the federated-frontend container conventions) is governed by the
kernel's *host* contract and lives outside the ABI freeze. Apps embedding the
kernel can still observe semantic versioning on those surfaces — see
`CHANGELOG.md`.

The kernel package declares the manifest-side counterpart of this contract as
`manifest.APIVersion = "2.0.0"` — that constant tracks the *manifest schema*
revision, which entered v1 of the ABI at its 2.0.0 cut. The two numbers will
continue to be independent: an additive manifest revision can land inside ABI
v1 without renaming this document.

## 2. Manifest spec v1.0

A manifest is a JSON object whose top-level shape is `manifest.Manifest`
(`manifest/manifest.go`). The fields below are part of the v1 contract; any
field not listed here is implementation-internal and may be removed.

### 2.1 Identity fields

| Field             | Type     | Required | Stable in v1 | Notes |
| ----------------- | -------- | -------- | ------------ | ----- |
| `key`             | string   | yes      | yes          | Must match `^[a-z][a-z0-9_]{1,63}$`. Used as the Postgres schema suffix (`addon_<key>`). |
| `name`            | string   | yes      | yes          | Human-readable. |
| `description`     | string   | no       | yes          | |
| `version`         | string   | yes      | yes          | Semver. |
| `category`        | string   | no       | yes          | Free-form. |
| `kernel`          | string   | no       | yes          | Semver range, e.g. `">=0.10 <2"`. Empty = legacy / no constraint. |
| `author` / `website` / `license` / `readme` / `screenshots` / `features` / `price` | strings/arrays | no | yes | Marketplace metadata. Opaque to the runtime. |

### 2.2 Icons

`icon` (legacy string), plus the explicit triplet `icon_type` /
`icon_slug` / `icon_color`. `icon_type` MUST be one of `brand` (simple-icons
slug), `lucide` (PascalCase icon name) or `url` (absolute URL). All four
fields are optional.

### 2.3 Tenant isolation

`tenant_isolation` selects how the addon's data is partitioned per
organization. Closed set:

| Value                 | Behaviour                                                                        |
| --------------------- | -------------------------------------------------------------------------------- |
| `""` (empty)          | Same as `"shared"`. Treated as the legacy / default value for retro-compat.      |
| `shared`              | Single schema `addon_<key>`, every table carries `organization_id`, Postgres RLS. |
| `schema-per-tenant`   | One schema per installation (`addon_<key>_<orgshort>`). Created on install, dropped on uninstall. |
| `database-per-tenant` | Reserved for v1.x; rejected by the v1.0 installer.                                |

### 2.4 Models

`models[]` is metadata (`Module{key, label}`); the actual table layout lives
in `model_definitions[]`:

```jsonc
"model_definitions": [{
  "table_name": "tickets",
  "model_key":  "tickets",
  "label":      "Tickets",
  "org_scoped": true,
  "soft_delete": true,
  "columns": [ /* ColumnDef ... */ ],
  "relations": [ /* RelationDef ... */ ]
}]
```

#### 2.4.1 `ColumnDef`

| Field        | Type     | Stable | Notes |
| ------------ | -------- | ------ | ----- |
| `name`       | string   | yes    | `^[a-z][a-z0-9_]{0,62}$`. |
| `type`       | string   | yes    | One of `string`, `uuid`, `int`, `bigint`, `decimal`, `bool`, `timestamp`, `jsonb`, `text`. |
| `size`       | int      | yes    | For varchar widths and similar. |
| `required`   | bool     | yes    | |
| `index`      | bool     | yes    | btree DDL. |
| `unique`     | bool     | yes    | |
| `default`    | string\|number\|bool\|null | yes | Coerced to a DDL-safe literal at install. Allowed forms: numeric (`42`), single-quoted string (`'pending'`), built-ins `now()`, `gen_random_uuid()`, `uuid_generate_v4()`, `current_timestamp`, `true`, `false`, `null`. Any other value is rejected. |
| `ref`        | string   | yes    | FK target, `"<table>"` or `"<schema>.<table>"`. |
| `visibility` | string   | yes    | Closed set: `""` (= `all`), `all`, `table`, `modal`, `list`. |
| `searchable` | bool     | yes    | UI / search-index opt-in (independent from `index`). |
| `widget`     | string   | yes    | Closed set: `text`, `textarea`, `select`, `multi_select`, `search`, `number`, `date`, `datetime`, `email`, `url`, `boolean`, `image`, `file`, `richtext`, `json`, `relation`, `password`, `slider`, `rating`. Empty = inferred from `type`. |
| `validation` | object   | yes    | `ValidationRule` — `regex`, `min`, `max`, `custom`. See 2.4.3. |

#### 2.4.2 `RelationDef`

Closed set of `kind` values in v1.0: `one_to_many`, `many_to_many`,
`belongs_to`. The fields are:

| Field         | Required when                       | Notes |
| ------------- | ----------------------------------- | ----- |
| `name`        | always                              | Snake-case identifier, unique per model. |
| `kind`        | always                              | See above. |
| `through`     | always                              | Target model / table name. |
| `foreign_key` | always                              | Column carrying the relationship. |
| `references`  | optional                            | Defaults to `"id"`. |
| `pivot`       | required iff `kind=many_to_many`    | Forbidden for `one_to_many` / `belongs_to`. |

#### 2.4.3 `ValidationRule`

`regex` (Go `regexp/syntax`), `min`, `max` (floats, bound numerics or
length), `custom` (either a dotted identifier `^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$`,
e.g. `email.basic`, or an org-config reference `^\$org\.[a-z][a-z0-9_]*$`,
e.g. `$org.tax_id_validator`). The regex is compiled at install time so
syntax errors fail loudly.

### 2.5 Navigation

`navigation[]` is `NavGroup{title, icon, target?, items[]}`. Each `NavItem`
is `{title, url?, icon?, model?, permission?, items?}`. `target` (when set)
merges into a host sidebar group like `"sidebar.sales"`; absent groups land
under "Addons".

### 2.6 Frontend

```jsonc
"frontend": {
  "entry":      "frontend/remoteEntry.js",
  "format":     "federation",
  "expose":     "./plugin",
  "container":  "metacore_<addonKey>",
  "integrity":  "sha384-...",
  "layout":     "shell"
}
```

- `format`: `federation` (recommended), `script` (legacy `window.__addon`
  registration), or empty.
- `layout`: `""` (= `shell` for legacy), `shell` (default chrome), or
  `immersive` (full-viewport takeover — POS terminals, kitchen displays,
  customer-facing kiosks).
- `container`: when empty the SDK derives `metacore_<key>` deterministically;
  if set it MUST match the `name` option of `@originjs/vite-plugin-federation`
  at build time.

### 2.7 Backend

```jsonc
"backend": {
  "runtime":         "wasm",
  "entry":           "backend/backend.wasm",
  "exports":         ["resolve_ticket", "ping"],
  "url":             "https://example.com/hook",
  "memory_limit_mb": 64,
  "timeout_ms":      10000
}
```

| Field              | Stable | Notes |
| ------------------ | ------ | ----- |
| `runtime`          | yes    | Closed set: `webhook`, `wasm`, `binary`. `binary` is **reserved**: declared as valid by `manifest.Validate` but no `runtime/binary/` implementation ships in v1.0. Manifests that select it install OK at the manifest layer but the kernel will refuse to dispatch. |
| `entry`            | yes    | Required when `runtime=wasm`. Bundle-relative path under `backend/`. |
| `url`              | yes    | Webhook base URL (`runtime=webhook`). |
| `exports`          | yes    | Whitelist of guest functions the host may dispatch. The wasm host refuses every function name not in this list (`runtime/wasm/wasm.go` `invokeImpl`). |
| `memory_limit_mb`  | yes    | Default 64. Bounded above by the host's global ceiling (currently 256 MiB). |
| `timeout_ms`       | yes    | Default 10000. Per-invocation wall-clock cap. |

### 2.8 Capabilities

`capabilities[]` is the addon's request-time permission set. Each entry is
`{kind, target, reason?}`. Kinds in v1.0 (closed set enforced by
`security/enforcer.go` and `runtime/wasm/capabilities.go`):

| Kind              | Target shape                                          | Enforced by                              |
| ----------------- | ----------------------------------------------------- | ---------------------------------------- |
| `db:read`         | `<schema>.<table>` or `<schema>.*`                    | `db_query` host import.                  |
| `db:write`        | `<schema>.<table>` or `<schema>.*`                    | `db_exec` host import.                   |
| `http:fetch`      | URL pattern (`https://api.stripe.com/*`)              | `http_fetch` host import + egress SSRF guard. |
| `event:emit`      | event name or `prefix.*`                              | `event_emit` host import via `events.Bus.Publish`. |
| `event:subscribe` | event name or `prefix.*`                              | `events.Bus.Subscribe`.                  |

Manifest validation rejects bare `*` for `db:read` / `db:write` and any
TLD-less `http:fetch` target (defends against link-local / loopback / private
ranges). The implicit `db:read addon_<key>.*` and `db:write addon_<key>.*`
capabilities are granted automatically for the addon's own schema; cross-
schema reads or writes need an explicit declaration.

### 2.9 Hooks

`hooks` is a `map[string]string` of `"<model>::<action>"` → webhook URL. The
v1 contract is:

- The map drives the legacy webhook dispatcher (`bridge/actions.go`) for
  `runtime=webhook`.
- When `backend.runtime=wasm` is set, every `<action>` half of every key
  MUST appear in `backend.exports` — `manifest.Validate` rejects the
  manifest otherwise.

### 2.10 Actions

`actions` is `map[<model>][]ActionDef`. Each `ActionDef` is:

```jsonc
{
  "key":             "approve",
  "name":            "Approve",
  "label":           "Approve ticket",
  "icon":            "Check",
  "fields":          [ /* FieldDef ... */ ],
  "requiresState":   ["pending"],
  "confirm":         true,
  "confirmMessage":  "Approve and notify?",
  "modal":           "approve_modal",
  "trigger": { "type": "wasm", "export": "approve_ticket", "run_in_tx": true }
}
```

`FieldDef` is the same shape used by `model_definitions[].columns[]` for UI
form rendering: `{name, label, type, required?, default?, options?, size?}`.

### 2.11 Tools (LLM-facing actions)

`tools[]` is the conversational-host plane. Each entry is `ToolDef`:

```jsonc
{
  "id":            "search_orders",
  "name":          "Search orders",
  "description":   "Search orders by customer email or order ID.",
  "category":      "query",
  "input_schema":  [ { "name": "query", "type": "string", "required": true } ],
  "trigger_keywords": ["order", "pedido"],
  "trigger_intents":  ["search_order"],
  "endpoint":      "/api/tools/search-orders",
  "method":        "POST",
  "timeout":       30,
  "cache_ttl":     60,
  "priority":      10
}
```

The kernel does not run tools itself — `bridge/tools.go` projects them into
a host `ToolStore` interface the consuming app implements. The shape is
stable in v1 so tools authored for one conversational host run on any other.

### 2.12 Settings

`settings[]` is `SettingDef{key, label, type, default_value?, options?, secret?}`.
Per-installation; secrets are encrypted at rest by the installer and
delivered to the guest via the `env_get` host import.

### 2.13 Lifecycle hooks

`lifecycle_hooks` is `map[string][]HookDef`. The five lifecycle phases the
kernel emits are `install`, `enable`, `disable`, `uninstall`, and `boot`
(see `lifecycle/lifecycle.go`). Each `HookDef` is `{event, target, priority?,
async?}` where `target.type` is one of `webhook` (HTTP, `target.url`
required), `wasm` (in-process, `target.function` required and listed in
`backend.exports`), or `prompt` (LLM completion, `target.prompt` required).

> **Frozen-as-is caveat.** The `lifecycle_hooks` field IS part of the v1.0
> manifest schema, but the kernel v0.10.1 does not yet route hook dispatch
> through it for compiled / WASM addons — the registered `lifecycle.Addon`
> interface (`OnInstall`, `OnEnable`, `OnDisable`, `OnUninstall`) is the
> active path. The field is reserved for declarative dispatch; manifests
> that include it install cleanly but the entries are observational. See
> § 12 for the explicit deprecation note.

### 2.14 Events (declarative)

`events[]` is `[]string` — a publish-side declaration of canonical event
names the addon emits. It is currently advisory: the kernel does NOT consult
it. The authoritative gate is `capabilities[]` (`event:emit <name>`). See
§ 12.

### 2.15 Signature

`signature` is `Signature{developer_id, developer_name, verified, signed_at,
algorithm, digest, value, checksums?}`. In v1.0 only `ed25519` is honoured.
The bundle SHA-256 is hex-encoded in `digest`; the signed payload is the raw
tarball bytes; `value` is the hex-encoded Ed25519 signature over the digest
bytes. `checksums` (optional) is `map[string]string` of bundle-relative path
→ hex-encoded SHA-256 of the file contents — used for per-file integrity.

### 2.16 Permissions (legacy)

`permissions[]` (`Permission{model, scope, reason?}`) is the legacy
declarative model/scope access list, kept for retro-compat. New addons MUST
use `capabilities[]` — `permissions[]` is preserved for v1 but receives no
new fields and will be removed in v2.

### 2.17 i18n

`i18n` is `map[<locale>]map[<key>]string` — flat key/value catalog keyed by
BCP-47 locale tag. Consumed by the host's i18n service; transparent to the
runtime.

### 2.18 Identifier alphabets (normative)

| Identifier             | Regex                                       | Used for |
| ---------------------- | ------------------------------------------- | -------- |
| Addon key              | `^[a-z][a-z0-9_]{1,63}$`                    | `manifest.key`, schema suffix. |
| Model / table          | `^[a-z][a-z0-9_]{0,63}$`                    | `model_definitions[].table_name`, relation `through` / `pivot`. |
| Column                 | `^[a-z][a-z0-9_]{0,62}$`                    | `columns[].name`, relation `foreign_key` / `references` / `name`. |
| WASM export            | `^[A-Za-z_][A-Za-z0-9_]{0,127}$`            | `backend.exports[]`, `trigger.export`. |
| Custom validator slug  | `^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$`     | `validation.custom`. |
| Org-ref validator      | `^\$org\.[a-z][a-z0-9_]*$`                  | `validation.custom` (org-config swap-in). |
| Event name             | `^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)*$`     | `capabilities[].target` for `event:emit` / `event:subscribe`, payload to `event_emit` host import. Subscribe patterns may end in `.*`. |

## 3. Bundle format v1.0

A bundle is a single `.tar.gz` produced by `bundle.Write` and consumed by
`bundle.Read`. The format is reproducible: entries are emitted in a fixed
order with `mtime = unix 0` and `Format = tar.FormatPAX`, so two identical
inputs produce byte-identical outputs.

### 3.1 Layout (frozen in v1.0)

```
manifest.json              (required — parsed into manifest.Manifest)
migrations/0001_init.sql   (optional — applied in lexicographic order)
migrations/0002_*.sql
frontend/remoteEntry.js    (optional — federated UI entry)
frontend/assets/*          (optional — static assets, opaque)
backend/backend.wasm       (required when backend.runtime=wasm; opaque to the bundler)
README.md                  (optional)
```

Paths use forward slashes, are relative (no leading `/`), and contain no
`..` segments. The reader rejects any path that violates these rules.

### 3.2 Decompression safety

Bundles ship with a host-side cap (default 64 MiB) on decompressed size.
Both per-entry and aggregate enforcement is over **bytes actually read**,
not the self-reported tar header.

### 3.3 Per-file digests

`bundle.Read` hashes every regular entry with SHA-256 and exposes the hex-
encoded results in `Bundle.EntryDigests`. The security verifier
(`security/signature.go`) cross-checks every entry in
`manifest.signature.checksums` against this map AND refuses any
undeclared entry (except `manifest.json`, which cannot self-checksum).
Bundles signed before checksums landed leave the field empty and skip the
extra verification — they still gain the global Ed25519 over the whole
tarball.

### 3.4 Migrations

Each `migrations/<version>.sql` file is one Postgres migration. The
`<version>` token MUST be a stable sort key (e.g. zero-padded numeric
prefix like `0001_init`); the installer applies them in lexicographic
order. Migrations run inside the addon schema; cross-schema DDL needs an
explicit grant outside the v1 surface.

## 4. WASM ABI v1.0

The wire-level contract between the host (`runtime/wasm/`) and a compiled
guest module. The implementation lives at `runtime/wasm/abi.go` and
`runtime/wasm/wasm.go`.

### 4.1 Guest exports (required)

A v1 guest module MUST export:

| Symbol           | Signature                       | Purpose |
| ---------------- | ------------------------------- | ------- |
| `memory`         | `(memory $name "memory")`       | The module's default linear memory. The host reads / writes through it. |
| `alloc`          | `func(size i32) -> i32`         | Bump or pool allocator. Returns the guest pointer of `size` reserved bytes. Must succeed for any size up to `memory_limit_mb` MiB. |
| `<export>`       | `func(ptr i32, len i32) -> i64` | One per entry in `backend.exports[]`. `(ptr, len)` is the request payload (JSON, by convention). The return is a packed pointer (see 4.2). |

The host ALSO uses `alloc` to write **response** buffers back into guest
memory (for `env_get`, `http_fetch`, `db_query`, `db_exec`, `event_emit`
when they return data).

### 4.2 Pointer/length encoding

Every i64 carrying buffer location packs `(ptr<<32) | len`:

```
result_i64 = (uint64(ptr) << 32) | uint64(len)
```

Both halves are interpreted as unsigned 32-bit. A return value of `0`
(`ptr=0, len=0`) is reserved for "empty success" on guest exports;
specific host imports document their own zero-encoding (see § 5).

### 4.3 Invocation surface (host side)

The host exposes two entry points (`runtime/wasm/wasm.go`):

| Entry point        | Used by                                                   | Behaviour |
| ------------------ | --------------------------------------------------------- | --------- |
| `Host.Invoke`      | Webhook adapter, lifecycle hooks, any non-action caller. | Calls the export. `db_exec` from inside this path returns `db_unavailable` unless a standalone `db` handle is wired (see § 5.5). |
| `Host.InvokeInTx`  | Action bridge, when `Trigger.Type=wasm` and `RunInTx=true`. | Stashes the open `*gorm.DB` transaction on the per-invocation context bag. `db_exec` then executes on that tx so the guest's writes commit / rollback with the action. |

Both entry points serialise per `(addonKey, installation)` — wazero is not
reentrant per memory, so only one call at a time runs against a given
instance.

### 4.4 Instance lifecycle

- One CompiledModule per addon (cached on `Host.compiled`).
- One Module instance per `(addonKey, installation)` (cached on
  `Host.modules`). Reloading the addon (`Host.Load`) drops every prior
  instance.
- Each invocation is a plain function call against the cached instance.
  Module-level globals persist between invocations *within the same
  installation*; they reset when the host is rebuilt or the module
  reloaded. Authors SHOULD NOT rely on cross-invocation state.

### 4.5 Memory & reentrancy rules

- Pointers passed across the boundary are valid only for the duration of a
  single host import call. After the host returns control to the guest, the
  guest is free to overwrite or reuse the underlying bytes.
- Buffers returned by host imports are copied out before the guest's next
  allocation (the host returns the packed pointer, the guest reads its bytes
  immediately).
- Host imports are synchronous. The guest cannot register callbacks.
- The kernel does NOT expose stdin / stdout / stderr. The only observable
  side-effects are through `metacore_host` imports.

### 4.6 Timeouts

`backend.timeout_ms` (default 10 000) bounds the wall-clock time of a single
invocation. Exceeding it aborts the instance; the host returns an error to
its caller. The `db_query` / `db_exec` host imports impose their own
per-call deadline (default 5 s) — the lower of the two wins.

### 4.7 Error surface

By convention, errors are reported INSIDE the guest's return envelope:

```jsonc
{ "error": { "code": "not_found", "message": "ticket 42 missing" } }
```

Hosts forward this verbatim to the caller (HTTP response, action result,
tool invocation). Panics, abort traps, and timeouts are reported by the
host as `{"code":"runtime_error"}` / `{"code":"timeout"}` envelopes.

## 5. Host imports (`metacore_host` module)

Every guest can import these. All pointer parameters reference guest memory.

```
log(msgPtr i32, msgLen i32)
env_get(keyPtr i32, keyLen i32) -> i64
http_fetch(urlPtr, urlLen, methPtr, methLen, bodyPtr, bodyLen i32) -> i64
event_emit(eventPtr, eventLen, payloadPtr, payloadLen i32) -> i64
db_query(sqlPtr, sqlLen, argsPtr, argsLen i32) -> i64
db_exec(sqlPtr, sqlLen, argsPtr, argsLen i32) -> i64
```

The host writes any response buffer into guest memory via the guest's own
`alloc` export and returns the packed pointer.

### 5.1 `log`

```
log(msgPtr i32, msgLen i32) -> void
```

Writes a structured log line tagged with the addon key and installation id
through the host's `*log.Logger`. The host's logger is always non-nil.
Failure modes (out-of-memory read) are silently dropped — `log` is fire-and-
forget.

### 5.2 `env_get`

```
env_get(keyPtr i32, keyLen i32) -> i64
```

Returns the per-installation setting value as a packed pointer in guest
memory. Returns `0` (empty success / not packed pointer) if the key is
missing or has an empty value. Keys correspond to `manifest.settings[].key`;
secrets are delivered as plaintext to the guest.

### 5.3 `http_fetch`

```
http_fetch(urlPtr, urlLen, methPtr, methLen, bodyPtr, bodyLen i32) -> i64
```

Performs an outbound HTTP request. `method` defaults to `GET` when empty.
Body, when non-empty, is sent with `Content-Type: application/json`. The
SSRF / egress guard (`security.Capabilities.CanFetch`) runs BEFORE any
syscall.

Returns a packed pointer to a JSON envelope:

```jsonc
{ "status": 200, "body": "<response body as string>" }
```

Response bodies are capped at 8 MiB. Failures surface as JSON error
envelopes:

```jsonc
{ "error": "forbidden",   "message": "<egress guard reason>" }
{ "error": "bad_request", "message": "<http.NewRequestWithContext failure>" }
{ "error": "transport",   "message": "<dial/timeout failure>" }
```

Wall-clock cap for the underlying request is 30 s, independent of
`backend.timeout_ms`. The two bounds run in parallel.

### 5.4 `db_query` — scoped read SQL

```
db_query(sqlPtr, sqlLen, argsPtr, argsLen i32) -> i64
```

Issues a single `SELECT` (or `WITH … SELECT`) statement inside a freshly
opened transaction with `SET LOCAL search_path TO addon_<key>, public`.
Read-only by construction (mutating keywords are rejected at the string
layer; banned keywords list is enumerated in `runtime/wasm/dbquery.go`).

**Capability gate.** When an `Enforcer` is wired, the addon must hold
`db:read addon_<key>.*` (the implicit self-schema capability). Cross-schema
reads are NOT walked in v1.0 — `SET LOCAL search_path` masks bare names but
explicit `public.<table>` references currently bypass the per-relation
check. See § 12 for the deprecation note.

**Response envelope.** Always populated. Success shape:

```jsonc
{
  "success": true,
  "data": {
    "rows":     [ { "id": 1, "title": "..." }, ... ],
    "rowCount": 42,
    "columns":  [ { "name": "id", "type": "int8" }, { "name": "title", "type": "text" } ]
  },
  "meta": { "schema": "addon_tickets", "durationMs": 7, "truncated": false }
}
```

Failure shape:

```jsonc
{
  "success": false,
  "error":   { "code": "<code>", "message": "..." },
  "meta":    { "schema": "addon_<key>", "durationMs": <int64> }
}
```

Defined error codes in v1.0:

| Code                  | When |
| --------------------- | ---- |
| `invalid_sql`         | Banned keyword, multi-statement, non-`SELECT` lead, empty body. |
| `arg_decode`          | `argsPtr/argsLen` is not a JSON array, or contains an unsupported value. |
| `forbidden`           | Capability check failed. |
| `row_limit_exceeded`  | Result exceeded 10 000 rows, or envelope > 8 MiB. |
| `db_error`            | Underlying driver/SQL error. |
| `db_unavailable`      | Host was constructed without `WithDB`. |

**Limits.**

| Knob               | Default |
| ------------------ | ------- |
| Max SQL length     | 16 KiB  |
| Max args           | 64      |
| Per-call deadline  | 5 s     |
| Max rows           | 10 000  |
| Max response bytes | 8 MiB   |

**Argument encoding.** JSON array; values map to driver-native types:

| JSON                       | Postgres type   |
| -------------------------- | --------------- |
| `null`                     | NULL            |
| `true` / `false`           | bool            |
| integer literal            | int8            |
| floating literal           | float8          |
| string                     | text            |
| `{"$bytes": "<base64>"}`   | bytea           |
| `{"$uuid":  "<uuid>"}`     | uuid            |
| `{"$ts":    "<RFC3339>"}`  | timestamptz     |

Plain nested arrays / objects are rejected with `arg_decode`. JSON args use
`UseNumber` so integers fit in int64 without float promotion.

### 5.5 `db_exec` — scoped mutation SQL

```
db_exec(sqlPtr, sqlLen, argsPtr, argsLen i32) -> i64
```

Issues a single `INSERT` / `UPDATE` / `DELETE` / `MERGE` statement. Multi-
statement payloads, `SELECT`, DDL, tx-control verbs (`BEGIN`, `COMMIT`,
`ROLLBACK`, `SAVEPOINT`, `RELEASE`), and privilege verbs (`GRANT`, `REVOKE`)
are rejected at the string layer.

**Transaction reuse.** When the host entered via `Host.InvokeInTx`, the
import runs on the supplied `*gorm.DB` transaction — the guest's writes
commit / rollback atomically with the surrounding action. When the host
entered via `Host.Invoke`, the import opens its own short-lived transaction
on the standalone DB handle. When neither is available, the import returns
`db_unavailable`.

**Capability gate.** Implicit `db:write addon_<key>.*` for the addon's own
schema; cross-schema writes require an explicit grant.

**Response envelope.** Success:

```jsonc
{
  "success": true,
  "data":    { "rowsAffected": 3 },
  "meta":    { "schema": "addon_<key>", "durationMs": 11 }
}
```

Failure:

```jsonc
{
  "success": false,
  "error":   { "code": "<code>", "message": "..." },
  "meta":    { "schema": "addon_<key>", "durationMs": <int64> }
}
```

Defined error codes in v1.0:

| Code                  | When |
| --------------------- | ---- |
| `invalid_sql`         | Multi-statement, non-mutation lead, banned keyword. |
| `arg_decode`          | Same shape as `db_query`. |
| `forbidden`           | Capability check failed. |
| `db_error`            | Underlying driver/SQL error. |
| `db_unavailable`      | Neither `tx` nor `db` available on the invocation. |

Limits and argument encoding mirror `db_query`. `RETURNING` rows are NOT
projected in v1.0 — only `rowsAffected` is reported. See § 12.

### 5.6 `event_emit` — domain-event publish

```
event_emit(eventPtr, eventLen, payloadPtr, payloadLen i32) -> i64
```

Publishes `<event>` + `<payload>` through the kernel's in-process
`events.Bus`. The guest contributes name + bytes; the host owns the bus,
the capability check, and the tenant scoping.

**Event-name contract.**

- Non-empty, length ≤ 256 bytes, valid UTF-8.
- Recommended shape `^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)*$` (matches the
  capability target alphabet). The host's runtime validation enforces non-
  empty + length + UTF-8 in v1.0; the per-segment shape is enforced by the
  capability check ahead of `Publish`.

**Payload contract.** Opaque bytes. Recommended UTF-8 JSON for tooling
compatibility. Empty payload (`payloadLen=0`) is delivered as `nil` to
subscriber handlers. Hard cap: 256 KiB.

**Return value (v1.0).** `0` on success (the publish fanned out, however
many subscribers matched). On failure, a packed pointer to a JSON error
envelope:

```jsonc
{ "error": "bus_unavailable",     "message": "host has no events.Bus configured" }
{ "error": "invalid_event",       "message": "<empty|too_long|not_utf8|out_of_memory>" }
{ "error": "payload_too_large",   "message": "payload exceeds 262144 bytes" }
{ "error": "invalid_payload",     "message": "payload out of guest memory" }
{ "error": "forbidden",           "message": "<capability/enforcer reason>" }
```

> The wasm-abi.md proposal document discussed a richer success envelope
> shape (`{success:true, data:{event, subscribers}, meta:{...}}`). That
> shape is NOT in v1.0; the implemented contract returns `0` on success.
> Adding the richer envelope is a candidate v1.x additive change (the
> guest can disambiguate "old success = 0" from "new success != 0" by
> checking `len != 0`).

**Tenant scope.** The host call site passes `inv.orgID` to
`events.Bus.Publish`. In v1.0 the kernel's `Host.Invoke` / `Host.InvokeInTx`
do not yet thread `orgID` onto the per-invocation context bag, so
event_emit publishes under `uuid.Nil` until callers opt in. The bus
matcher does NOT filter handlers by org; subscribers receive `orgID` and
apply their own filtering. See § 12.

**Capability gate.** Delegated to `events.Bus.Publish` →
`Enforcer.CheckCapability(addonKey, "event:emit", event)`. Wildcard
declarations (`tickets.*`) work as documented. In `ModeShadow` a missing
capability logs but does not block; in `ModeEnforce` it returns
`forbidden`.

## 6. Lifecycle hooks

Compiled addons (registered through `Host.RegisterCompiled`) implement the
`lifecycle.Addon` interface:

```go
type Addon interface {
    Manifest() manifest.Manifest
    OnInstall(db *gorm.DB, orgID uuid.UUID) error
    OnUninstall(db *gorm.DB, orgID uuid.UUID) error
    OnEnable(db *gorm.DB, orgID uuid.UUID) error
    OnDisable(db *gorm.DB, orgID uuid.UUID) error
}
```

The four phases run synchronously inside the installer transaction. An
optional `Bootstrapper` interface:

```go
type Bootstrapper interface {
    Boot(ctx *BootContext) error
}
```

runs once at process boot, after the registry is built, with the shared
`*gorm.DB` and the host-supplied `Services` map (event bus, push, ws hub,
etc. — see `BootContext.GetService`).

WASM addons in v1.0 do NOT receive lifecycle hooks through their compiled
module — the host applies the addon's migrations and registers metadata
itself, but does not invoke any guest export named `on_install` /
`on_enable` / etc. Declarative `lifecycle_hooks` entries are accepted by
the manifest validator but are reserved (§ 12).

## 7. Action triggers

`actions[].trigger` declares how the kernel dispatches an action when the
host invokes it. Closed set of `type` values in v1.0:

| Type      | Required fields                  | Behaviour |
| --------- | -------------------------------- | --------- |
| `wasm`    | `export` (in `backend.exports`)  | Invoke the named export. `run_in_tx=true` enters via `Host.InvokeInTx`. |
| `webhook` | none (URL via `hooks` or `backend.url`) | Dispatch via HMAC-signed webhook. `export` and `run_in_tx` MUST be empty/false. |
| `noop`    | none                             | UI-only marker; no addon code runs. |

A manifest with no `trigger` field on an action falls back to the legacy
behaviour: the action is registered with a webhook URL resolved from
`hooks["<model>::<action>"]`; if none is declared the registry stores a
no-op interceptor so the UI still shows the button.

## 8. Event bus contract

The kernel's in-process `events.Bus` is the canonical fan-out plane.

### 8.1 Wire shape

Published events carry four positional arguments to every subscriber:

```go
type Handler func(ctx context.Context, orgID uuid.UUID, payload any) error
```

- `ctx`: the context of the publisher (HTTP request, action call, wasm
  invocation).
- `orgID`: the publisher's tenant. Subscribers MUST use this for their own
  row-level filtering; the bus does not pre-filter by org.
- `payload`: opaque to the bus. Kernel-internal publishers send typed Go
  structs; cross-addon publishers send `json.RawMessage`.

### 8.2 Naming convention

The kernel publishes CRUD events as `<addonKey>.<model>.<action>` (e.g.
`tickets.tickets.created`, `kernel.users.updated`). The `addonKey` segment
is `"kernel"` for host-owned models — the bus bypasses the capability check
for that producer. Addons that publish through `event_emit` set the
producer to their own key; the bus calls `Enforcer.CheckCapability(addonKey,
"event:emit", event)` before fan-out.

Canonical CRUD payload shape (`dynamic.CanonicalEvent`):

```jsonc
{
  "id":     "<row id>",
  "before": { /* row state before the mutation, omitted on `created` */ },
  "after":  { /* row state after the mutation, omitted on `deleted` */ }
}
```

### 8.3 Subscribe wildcards

A pattern ending in `.*` matches every event sharing the prefix:
`tickets.*` matches `tickets.created`, `tickets.resolved`, etc., but not
`tickets-archive.created`. Only trailing-dot-star wildcards are honoured.
Publishing a wildcard name (`tickets.*` as the event) is invalid — the
matcher only handles wildcards on the subscribe side, and the capability
enforcer rejects wildcard publish-side targets.

## 9. Capability model

`security.Capabilities` (built from `manifest.capabilities[]`) gates every
privileged side effect at host-import time. The set of kinds is closed in
v1.0 (§ 2.8). The matcher honours trailing-dot-star wildcards on every
target.

The enforcer runs in two modes:

| Mode          | Behaviour |
| ------------- | --------- |
| `ModeShadow`  | A failing capability check logs the violation but lets the call through. Used during rollouts. |
| `ModeEnforce` | A failing capability check returns `forbidden`. Default in production. |

Mode is selected at boot via the `METACORE_ENFORCE` environment variable;
flipping it does not require a redeploy.

### 10.2 Hello-world WASM (TinyGo)

```go
// backend/main.go — exports `ping` per ABI v1.0.
package main

import (
    "encoding/json"
    "unsafe"
)

//go:wasmimport metacore_host log
func hostLog(ptr, length uint32)

//go:wasmimport metacore_host event_emit
func hostEventEmit(eventPtr, eventLen, payloadPtr, payloadLen uint32) uint64

// alloc is the bump allocator the host calls before writing the payload.
//
//go:export alloc
func alloc(size uint32) uint32 {
    buf := make([]byte, size)
    return uint32(uintptr(unsafe.Pointer(&buf[0])))
}

// ping receives a JSON payload, logs it, emits an event, returns a JSON reply.
//
//go:export ping
func ping(ptr, length uint32) uint64 {
    in := unsafe.Slice((*byte)(unsafe.Pointer(uintptr(ptr))), length)
    var req struct {
        Message string `json:"message"`
    }
    _ = json.Unmarshal(in, &req)

    msg := []byte("hello from wasm: " + req.Message)
    hostLog(uint32(uintptr(unsafe.Pointer(&msg[0]))), uint32(len(msg)))

    evt := []byte("hello.greeted")
    payload := []byte(`{"message":"` + req.Message + `"}`)
    hostEventEmit(
        uint32(uintptr(unsafe.Pointer(&evt[0]))), uint32(len(evt)),
        uint32(uintptr(unsafe.Pointer(&payload[0]))), uint32(len(payload)),
    )

    resp, _ := json.Marshal(map[string]string{"reply": "pong", "echo": req.Message})
    p := uint32(uintptr(unsafe.Pointer(&resp[0])))
    return (uint64(p) << 32) | uint64(len(resp))
}

func main() {} // required by TinyGo
```

Build:

```bash
tinygo build -target=wasi -opt=z -no-debug -o backend/backend.wasm ./backend/
```

Package as a bundle:

```bash
tar -czf hello.tgz \
    manifest.json \
    backend/backend.wasm \
    migrations/0001_init.sql
```

Install it via your host's installer (see `installer/installer.go`).

## 11. Stability & compatibility

ABI v1 is the kernel's first frozen surface. The contract is:

- **Patch releases (v0.10.x).** Bug fixes only. No additions, no removals.
- **Minor releases (v0.10.x → v0.11.x, v0.11.x → v0.12.x, …, while still in
  v1).** **Additive only.** New host imports, new manifest fields with
  meaningful zero defaults, new capability kinds, new column types or
  widgets — yes. Removing fields, tightening required identifiers, changing
  enum semantics — no. Existing v1 guests / manifests / bundles MUST keep
  working unchanged across every v1 minor.
- **Major releases (v2.0.0).** Breaking changes allowed. A v2 release MUST
  ship with at least one minor release of OVERLAP during which the kernel
  honours both v1 and v2; addons receive a deprecation window to migrate.
  The deprecation policy mirrors what `metacore-sdk` already promises for
  its TypeScript API.

The kernel-side `manifest.APIVersion` constant tracks the manifest schema
revision inside v1; it is bumped on every additive manifest change and does
not by itself signal a break in the ABI freeze.

### 11.1 What is NOT covered by v1

These are intentionally out-of-scope and may change without notice in any
release:

- HTTP routes mounted under `/api` by `host.App`. Apps consume them via the
  TS SDK; the route shape is governed by the SDK's own semver.
- The WebSocket protocol (`ws/`). Stable per minor, but evolves with the
  host product.
- The Prometheus metric names emitted by `metrics/`.
- The internal layout of `metacore_installations` / addon registry tables.
- `runtime/binary` (reserved manifest value, not implemented).
- The full envelope shape of `event_emit` success returns (today: `0`).

## 12. Known inconsistencies (informational, frozen-as-is in v1.0)

The audit that produced this freeze surfaced a small set of contract /
implementation gaps. They are documented here so addon authors can plan
around them; the v1.0 contract reflects the **implementation as shipped in
kernel v0.10.1**, not the (richer) proposals in `docs/wasm-abi.md`.

| # | Surface              | What the code does today                                                                                                  | What v1 promises | Resolution path |
|---|----------------------|---------------------------------------------------------------------------------------------------------------------------|------------------|-----------------|
| 1 | `manifest.lifecycle_hooks` | Declared in `manifest.Manifest`; validated by `manifest.Validate`; NOT read by the installer or wasm runtime.    | Reserved. Manifests including it install OK but the entries are observational. | Becomes active in a v1.x minor when declarative lifecycle dispatch lands. |
| 2 | `manifest.events`    | Declared in `manifest.Manifest`. Never consulted by the kernel.                                                            | Reserved as advisory. The authoritative event-publish gate is `capabilities[].event:emit`. | Either wire it as a discovery surface in v1.x, or drop in v2 (decided in advance, with notice). |
| 3 | `backend.runtime="binary"` | Accepted by `manifest.Validate`. No `runtime/binary/` implementation ships.                                          | Reserved. Manifests with this value parse OK but the kernel cannot dispatch them. | Land the side-car runtime in a v1.x minor, or drop the enum value in v2. |
| 4 | `event_emit` return envelope | Returns `0` on success. The proposal document (`docs/wasm-abi.md` § 12.4) shows a richer `{success, data:{event, subscribers}, meta}` envelope. | Today: `0` on success, packed JSON error envelope on failure. Additive: a future v1.x MAY start returning a packed envelope on success — guests already distinguish via `len != 0`. | Additive in v1.x once `events.Bus` grows a `PublishWithCount` sibling. |
| 5 | `event_emit` orgID   | The `invocation.orgID` field exists on the per-call context bag but `Host.Invoke` / `Host.InvokeInTx` never populate it. Today every guest-emitted event publishes under `uuid.Nil`. | Subscribers receive `uuid.Nil` and must handle it. | Additive: extend the invoke entry points to accept an `orgID` and stash it; guest contract unchanged. |
| 6 | `db_query` cross-schema reads | The validator rejects mutating keywords + introspection schemas at the string layer; it does NOT parse the AST or walk relation references. `SET LOCAL search_path` masks bare names, but an explicit `public.<table>` query bypasses per-relation capability checks (`Enforcer.CheckCapability(addonKey, "db:read", schema+".*")` only runs once for `addon_<key>.*`). | Self-schema reads are fully gated. Cross-schema reads through explicit qualifiers MAY succeed without matching `db:read <schema>.<table>` in v1.0. Authors SHOULD treat this as a soft guarantee and not rely on it for security. | Land a real Postgres AST walker in v1.x (`pg_query_go` is already an indirect dep) and tighten the gate; non-breaking because addons currently declaring the right capability will continue to pass. |
| 7 | `db_exec` `RETURNING` | The host runs `db.Exec(...)` and reports only `rowsAffected`. Statements may include `RETURNING`, but the projected rows are discarded. | Only `rowsAffected` is reported in v1.0. | Additive: surface `returning` rows in v1.x once the projection helper lands. |

All seven entries above are **documented contract** in v1.0 — the kernel
will keep behaving exactly as described for the entire v1 series, and any
deviation is a bug. Authors writing addons today should program against the
documented behaviour, not against the richer proposal text.
